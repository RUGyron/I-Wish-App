# Политика конфиденциальности

**Последнее обновление:** 4 мая 2026

## Главное

**Разработчик не видит содержимое ваших списков.** Имена списков, имена желаний, цены, ссылки, описания, фотографии и имена авторов — всё шифруется на вашем iPhone до того, как попасть в облако. Без ключа из вашего iCloud Keychain эти данные нельзя расшифровать.

## Что и где хранится

Приложение использует две независимые инфраструктуры:

### Google Firebase (хранилище данных)

В Firebase лежат **только зашифрованные блобы** + минимальные технические метаданные:

- идентификаторы (id списка, id желания, ваш UID, к какому списку вы присоединены),
- даты создания и изменения,
- сортировочные индексы и флаги архивации,
- цветовая «семя»‑константа для генерации обложки,
- размер зашифрованного содержимого.

Имена, описания, цены, ссылки, фотографии — лежат внутри одного бинарного поля `encryptedPayload`, расшифровать которое можно только клиентом, у которого есть ключ.

### Apple iCloud Keychain (ключи шифрования)

Каждому списку соответствует уникальный AES‑256‑GCM ключ. Эти ключи хранятся в **iCloud Keychain** (с включённой синхронизацией между вашими Apple ID‑устройствами). Apple передаёт их между вашими iPhone/iPad через end‑to‑end защищённый канал — **сама Apple ключи в открытом виде не видит**, разработчик — тем более.

Ваше отображаемое имя сохраняется там же (отдельным полем) и используется только для подписи «от <имя>» в общих списках.

## Что мы собираем

Никакой собственной аналитики, крашлитики или рекламных SDK. Сетевой обмен идёт только с двумя сторонами:

- **Firebase Auth** для входа через Apple ID,
- **Firebase Firestore** для хранения и синхронизации зашифрованных данных.

## Шеринг общих списков

Когда вы делитесь списком, приложение генерирует QR‑код / ссылку вида:

```
https://rugyron.github.io/I-Wish-App/j/<short-id>#k=<base64-key>
```

Часть после `#` (`fragment`) по спецификации HTTP **никогда не передаётся серверу** — браузер и iOS отрезают её ещё до отправки запроса. Поэтому ключ существует только у вас на экране и у получателя в QR/мессенджере; Firebase его никогда не видит.

Получатель сканирует QR (или открывает ссылку) — приложение читает ключ из памяти, сохраняет в его iCloud Keychain и расшифровывает содержимое. С этого момента он становится участником и может видеть/менять список в зависимости от выданной вами роли.

## Имя пользователя

При входе через Apple ID мы используем имя, которое Apple передаёт нам один раз — на первом входе. Имя сохраняется в вашем iCloud Keychain (приватно, синхронизируется между вашими устройствами) и затем подставляется в подпись «от <имя>» под желаниями, которые вы добавляете в общие списки.

В Firebase имя пользователя **не записывается** в открытом виде. Подпись попадает в общий список как часть зашифрованного содержимого — её увидят только участники с ключом.

## Доступы, которые приложение запрашивает

| Доступ | Зачем |
|--------|-------|
| Камера | Сканировать QR‑код приглашения, фотографировать обложку желания |
| Галерея | Выбрать фото обложки |
| Уведомления | Напомнить о конце «испытательного срока» желания (по желанию) |
| iCloud | Синхронизация ключей шифрования через Keychain |

Все доступы опциональны — без них работают остальные функции.

## Ваши права

- **Удалить локальные данные**: удалите приложение — локальный кеш и ключи в Keychain очищаются (после рестарта без подключённого iCloud Keychain — данные становятся нечитаемыми).
- **Удалить с серверов**: в настройках есть «Выйти из аккаунта» — удаляет локальный кеш. Чтобы стереть содержимое в Firebase — удалите свои списки из приложения, удалите участие в общих, или напишите разработчику.
- **Отозвать общий список**: любой выпущенный QR/ссылку можно отозвать в любой момент через карточку списка.
- **Сменить ключи**: переустановка приложения + новый Apple ID = заново сгенерированные ключи. Старые данные при этом потеряются (без ключа — нечитаемы).

## Если потеряете все устройства

Поскольку ключи живут только в вашем iCloud Keychain, **сброс iCloud Keychain Apple = потеря данных навсегда**. Это плата за то, что разработчик никогда не может в них заглянуть. У нас нет возможности восстановить ваши списки — только вы.

## Изменения

Если политика изменится — увидите обновление перед открытием приложения. Без вашего подтверждения новые правила в силу не вступают.
